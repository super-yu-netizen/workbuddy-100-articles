## 摘要

朋友甩来65页PDF项目方案，用WorkBuddy十分钟生成完整需求分析、191.6万报价方案和技术风险分级，再追问拆出纯开发成本186万与AI辅助省20%的对比路径。

## 正文

昨天下午，微信突然弹出来一条消息。

一个朋友甩了个文件过来，说："帮我看看这个项目需求，分析一下，给我一份分析报告和报价。"

我点开一看——65页的PDF。

某商融合平台项目方案手册。目录、需求、技术架构、功能清单、数据对象、部署方案、运营规划……全在里面。

65页。如果是以前，我得花至少一整天通读，再花两三天写分析报告，最后还得做个报价表。但现在我有了WorkBuddy。

十分钟后，我开始交东西了。

第一步：让AI读完65页

我把PDF文件直接发给WorkBuddy，说："看下这个项目需求，帮我分析下，给我一份分析报告和项目报价。"

WorkBuddy先调了pdf技能，装了pdfplumber，然后一口气把65页全读完了。

读完之后它说了一句很让我安心的话："内容全部读完了，65页，信息量很大。现在来生成分析报告和报价。"

不是"我大概看了看"，而是全部读完了。这个区别很大——后面所有的分析、报价、风险判断，都建立在完整阅读的基础上，不是摘要。

第二步：生成分析报告 + 报价

接下来WorkBuddy生了一份Word文档，打开一看——

结构是这样的：

需求分析部分：

-
• 归纳出7大核心痛点，每个痛点对应平台解决方案

-
• 拆解了4类服务对象（游客端、商家端、xx后台、AI导览）的具体需求

-
• 梳理了核心功能模块（6端+1中心+1底座的架构）

-
• 对现有演示原型的技术栈做了评估——哪些可用、哪些需要升级、哪些必须替换

到这里，如果只看表面，我已经有了"能交出去的东西"——一份完整的需求分析报告 + 一份报价方案。对于很多人来说，这就够了。

但我还不满足。

第三步：追问成本和技术风险

报告写的是"项目整体报价"——包含了硬件、云资源、运营、安全合规这些非开发成本。但我真正想知道的是：纯开发要花多少钱？有哪些技术坑？

所以我追问了一句："这里面的需要多少人工开发成本，和可能出现的技术难点？"

WorkBuddy的回答让我觉得它真的读懂了那65页——不只是提取了文字，而是做了工程判断。

但更让我震撼的是技术风险的判断——它把风险分成了三个等级：

🔴 高风险（决定项目成败）：

-
1. 多租户数据隔离 — 州下辖多个区县各自有独立的数据权限，州级看全域汇总，商家只看自己的数据。权限体系从演示模式的单一角色升级到6层权限边界。

-
2. 真实支付闭环 — 从模拟下单到微信/支付宝接入+退款+分账。任何bug直接影响商家资金安全。

-
3. 等保三级合规 — 不是开发能解决的，需要第三方测评机构，6-8周，额外费用15-20万。

-
4. AI内容安全 — 该地区是少数民族自治州，民族宗教敏感问题必须有人工质检闭环，不能纯靠LLM自由生成。

🟡 中风险：
SQLite→PG数据迁移、数字人终端生产部署、微信小程序适配。

🟢 低风险：
对象存储、短信通知、埋点、报表导出。

然后它还算了一笔隐性成本——68到105万，包括内容采集人力、等保测评第三方费、AI模型API调用费、硬件采购、运营团队首年人力。这些不在开发报价里但项目落地必须要有。

这一步的输出让我意识到：AI不只是帮你"写报告"，它帮你做了工程判断。哪些风险是致命的、哪些是可以容忍的、哪些隐性成本容易漏算——这些东西，如果你不是做过很多项目的架构师，你自己写不出来。

第四步：把分析变成可视化

口头分析写完了，但报告如果要给别人看，纯文字不够直观。

我让WorkBuddy用frontend-design技能，把成本和技术难点做成HTML页面。

出来的页面很漂亮——深海军蓝底色+琥珀金点缀，数据新闻风格。6张岗位成本卡片各带进度条，4阶段实施时间线，技术风险按红黄绿分级排列，底部隐性成本提醒框。

不是PPT截图，不是Word表格，是一个可以直接浏览器打开的交互页面。发给客户，对方打开就能看懂。

第五步：追问AI能不能省钱

最后我问了一个所有人都关心的问题："我如何用AI开发，成本会不会少一点？"

WorkBuddy没有简单地说"能省"或"不能省"，而是做了逐模块的对比分析：

AI能有效辅助的6类工作（标准化、重复性高）：

-
• CRUD API批量生成 → 省42%

-
• 前端页面组件 → 省38%

-
• 测试用例生成 → 省38%

-
• 文档和脚本 → 省50%

-
• 数据驾驶舱图表 → 省40%

-
• 运营后台标准功能 → 省33%

AI完全帮不上忙的4块（决定项目成败）：

-
• 多租户架构设计 → 必须人工

-
• 支付闭环接入 → 必须人工

-
• 等保三级合规 → 必须人工+第三方

-
• 民族宗教内容安全 → 必须人工定义规则

最终结论：传统开发186.3万 → AI辅助开发148万，省约38万（~20%）。

但它的建议不是"用AI砍人"，而是——用AI省下来的钱，多投一个资深架构师，专门把控那4个核心模块的质量。

这句话让我觉得它真的理解了这个项目。不是泛泛地说"AI能提高效率"，而是具体到"你这个项目，AI省的是CRUD的钱，但架构和安全不能省，所以应该把省下来的精力集中在决定成败的地方"。

复盘：AI做了什么，没做什么

整个流程走完，我回顾一下WorkBuddy在这个场景里的角色：

它做了的事：

-
1. ✅ 读完65页PDF，提取全部内容

-
2. ✅ 归纳7大痛点 + 4类服务对象需求

-
3. ✅ 评估现有技术栈的可用性

-
4. ✅ 生成9大类分项报价

-
5. ✅ 把人力成本拆到岗位级别

-
6. ✅ 做了技术风险的分级判断

-
7. ✅ 算了隐性成本

-
8. ✅ 做了传统 vs AI辅助的成本对比

-
9. ✅ 生成了Word报告 + 2个HTML可视化页面

它没做的事（也不应该做）：

-
1. ❌ 没有替我做最终决策——报价数字我核实过，有几处调整

-
2. ❌ 没有替我跟客户确认——方案档位的选择是我根据客户预算判断的

-
3. ❌ 没有替我做架构设计——它指出了多租户是高风险，但具体怎么设计还是需要架构师

-
4. ❌ 没有替我做等保合规——这个只能第三方机构做

一句话总结：AI帮你把"从65页PDF到可交付的分析+报价+风险全景"这条路上的所有体力活干完了，但最后的判断和决策，还是你的。

这套流程能复用到什么场景

不只是"有人甩PDF给你"这一种情况。这套分析流程可以复用到很多场景：

-
• 招投标分析：甲方发来招标文件，快速拆解技术要求和评分标准

-
• 竞品方案评审：对手的产品方案丢过来，拆出功能差异和技术短板

-
• 内部需求评审：产品团队写了50页需求文档，技术团队快速评估工作量

-
• 投资尽职调查：被投公司的技术文档，快速判断技术风险和真实成本

-
• 项目交接：前任留下的项目文档，快速理解现状和遗留问题

核心逻辑不变：AI读文档 → 归纳需求 → 评估技术 → 算成本 → 识别风险 → 生成可视化交付物。

几个实操建议

如果你也想用这套流程，有几个点值得注意：

-
1. PDF质量决定AI阅读质量。如果PDF是扫描件（图片型），AI提取文字会丢不少；如果是原生PDF（文字型），提取基本完整。这次这个PDF是原生PDF，所以65页全部成功提取。

-
2. 不要只看AI的报价数字，要追问依据。AI给的报价是基于方案手册里的信息推断的，不是你的实际人力成本。你需要把它的报价当作"参考框架"，然后根据你自己的团队实际情况调整。

-
3. 技术风险的判断比报价更重要。报价可以商量，但技术风险如果漏判，项目上线后才是真正的灾难。所以重点看AI对风险的分级判断，特别是那些标红的。

-
4. 隐性成本一定要算。AI帮我把等保测评费、内容采集人力、AI调用费这些容易漏算的成本单独拎出来了，这些加起来68-105万，跟开发报价差不多一个量级，不算的话项目预算一定爆。

-
5. 追问比一次提问更有价值。第一次我只问了"分析一下+报价"，得到了一份整体报告。第二次追问"纯开发成本和技术难点"，得到了更深层的拆解。第三次追问"AI能不能省钱"，得到了对比分析。每一轮追问都在上一轮的基础上更深入，这就是跟AI对话的正确方式——不是一次说完，而是层层递进。
